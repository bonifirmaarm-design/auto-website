# SKILL ROUTING — какой навык выбрать под задачу

**Правило:** перед написанием/правкой UI, фронтенда или любой визуальной части
СНАЧАЛА выбери и вызови подходящий навык из таблицы ниже через `Skill(...)`,
потом пиши код. Можно комбинировать несколько (например «стиль» + «ревью»).
Если задача не про UI/дизайн — навыки не нужны, работай как обычно.

## Как выбирать
1. Определи **этап**: создать новое / переделать существующее / отревьюить.
2. Определи **тип артефакта**: лендинг · продуктовый UI · компонент · форма ·
   презентация · баннер · 3D · дизайн-система.
3. Возьми навык(и) из соответствующей строки. При сомнении — универсальный
   `impeccable` (дизайн/редизайн/аудит/полировка) или `ui-ux-pro-max` (база знаний).

## Таблица маршрутизации

| Задача (триггер) | Навык(и) |
|---|---|
| Новый лендинг / промо / портфолио / «сайт-впечатление» | `frontend-design` → затем стиль: `taste-skill` / `hallmark` / `frontend-design-pro`; для скролл-историй `scroll-craft` |
| Продуктовый UI: дашборд, админка, SaaS, настройки, дата-интерфейс | `interface-design` + `ui-ux-pro-max`; реализация `ui-styling` |
| «Сделай красиво / премиально / не как шаблон» | `impeccable` или `soft-skill`; редизайн существующего — `redesign-skill` |
| Конкретный визуальный стиль | минимализм `minimalist-skill` · брутализм `brutalist-skill` · тёплый премиум `soft-skill` |
| По макету/картинке → в код | `image-to-code-skill` |
| Форма (регистрация, чекаут, настройки) | `form-design` (+ `ui-styling`) |
| Навигация (табы, дровер, иерархия) | `navigation-patterns` |
| Презентация / слайды | `slides` (+ `design-system` для токенов) |
| Баннер / соцсети / hero-креатив / печать | `banner-design` |
| Бренд: голос, айдентика, гайдлайны | `brand`; борды/лого-системы `brandkit` |
| 3D из референс-картинки (Three.js) | `img2threejs` |
| React/Next.js: производительность, архитектура компонентов | `react-best-practices` + `composition-patterns` |
| Анимации переходов между экранами (React) | `react-view-transitions` |
| Одна конкретная UI-анимация | `animation-principles`; полная спека — `micro-interaction-spec` |
| Состояния загрузки (скелетоны/спиннеры) | `loading-states` |

## Дизайн-система и токены (когда нужна системность)
| Задача | Навык |
|---|---|
| Общая архитектура токенов / компонентов | `design-system` |
| Слой токенов (цвет/отступ/тип/тени) | `design-token` |
| Цветовая система с нуля | `color-system`; тёмная тема — `dark-mode-design` |
| Типографика и шкала | `typography` (энфорс-правила) + `typography-scale` |
| Шкала отступов | `spacing-system` |
| Сетка страницы / брейкпоинты | `layout-grid` + `responsive-design` |
| Токены движения (длительности/easing) | `motion-system` |
| Визуальная иерархия | `visual-hierarchy` |

## Ревью / аудит (перед сдачей)
| Задача | Навык |
|---|---|
| Ревью UI-кода на best practices | `web-design-guidelines` |
| Юзабилити (Nielsen/Krug) | `ux-heuristics` |
| Доступность по WCAG | `accessibility-audit` |
| «Почини макет/цвета/шрифты» | `ui-refactor` |
| Системный визуальный аудит с планом | `design-audit` |
| Оригинальный визуальный язык (не «AI-generic») | `innovative-ux-designer` |
| Валидация продуктовой идеи | `design-sprint` |

## Дефолтный чек-лист для любой UI-задачи
1. Стиль/направление → один из: `frontend-design` / `taste-skill` / `impeccable` / `interface-design`.
2. Основа → `typography` + `color-system`/`design-token` + `spacing-system`/`layout-grid`.
3. Перед сдачей → `web-design-guidelines` + `accessibility-audit`.
